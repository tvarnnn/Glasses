# V0.9 — Experimental CV Lab: Design Spec

Status: Approved. Source of truth for the implementation plan.

## Context

`03-ROADMAP.md` V0.9 requires implementing Experimental CV Lab as the module
running in the V0.8 container, proving the complete pipeline end-to-end
through at least one bounded CV experiment to measured results, and
validating the module lifecycle/descriptor contract against real
implementation experience.

Currently `tower/main.py` hardcodes `ModuleContainer(BaselineCVModule())` —
`BaselineCVModule` is V0.8's placeholder, explicitly documented as
"V0.9 replaces this module in the same container slot with the real
Experimental CV Lab module." This spec is that replacement.

Confirmed before designing: `pyproject.toml` has no PyTorch dependency today
(only `fastapi`, `uvicorn`, `pillow`, `opencv-python-headless`, `numpy`,
`psutil`). This is load-bearing for the scope decision below.

## Non-goals (explicitly out of scope for V0.9)

- PyTorch, CUDA, TensorRT, CV-CUDA, DeepStream, or any other new dependency.
  No experiment in this milestone requires one. Adding PyTorch (even
  CPU-only) is the natural *next* experiment to run once this harness
  exists and profiling data shows OpenCV alone is insufficient — not a
  requirement of standing the Lab up.
- GPU utilization monitoring (`pynvml` or equivalent) — no GPU experiment
  exists yet to monitor.
- Dataset-recording sessions (`docs/modules/EXPERIMENTAL-CV.md` marks this
  optional).
- A dynamic/runtime experiment-switching API or plugin registry. The active
  experiment is chosen once, at process boot, via config — the same
  "registry of one until a second thing justifies generalizing" principle
  V0.8 already applied to modules, applied one level down to experiments.
- Sensor-profile settings beyond experiment selection (FPS/resolution
  negotiation is still deferred platform-wide per Rule 4).
- Any new backpressure/frame-dropping mechanism. The existing sequential
  `receive -> process -> ack` path in `tower/routes/ws.py` is unchanged;
  this milestone's instrumentation reveals its behavior under a heavier
  experiment rather than changing it.
- World Builder, Translator, SLAM, persistent spatial/object memory.
- Fixing V0.8's deferred review findings (event-loop lifecycle mismatch,
  resource leak on load-succeeds-start-fails) — both are verified still
  inert under this scope (see "V0.8 deferred issues" below), because both
  experiments in this milestone are stateless.

## Chosen approach

`ExperimentalCVModule` replaces `BaselineCVModule` in the container's one
hardcoded slot. It hosts exactly two stateless OpenCV experiments —
`baseline` (today's grayscale + mean intensity, reused verbatim from
`tower/frame_processing.py`, not reimplemented) and `edge_detection`
(Canny edge detection, deliberately ~5-10x costlier on identical input) —
selected once at boot via a config value, mirroring `TOWER_DEV_MODE`'s
existing pattern in `tower/config.py`.

Two alternatives were considered and rejected:
- Adding PyTorch (CPU) now with a model-based experiment from day one — rejected because it adds a large dependency before any profiling data justifies it, and front-loads V0.8's resource-leak concern into this milestone for no reason.
- A generalized, runtime-switchable experiment registry — rejected as the same speculative generalization V0.8 already deferred at the module level, now one layer down.

## Components

### `tower/instrumentation.py` (new)

```python
import time
from contextlib import contextmanager


class StageTimer:
    """Collects named-stage durations (ms) for one frame's processing."""

    def __init__(self) -> None:
        self._stage_ms: dict[str, float] = {}

    @contextmanager
    def stage(self, name: str):
        start = time.perf_counter()
        try:
            yield
        finally:
            self._stage_ms[name] = (time.perf_counter() - start) * 1000

    def snapshot(self) -> dict[str, float]:
        return dict(self._stage_ms)

    @property
    def total_ms(self) -> float:
        return sum(self._stage_ms.values())
```

A generic timing utility, not experiment-specific — reusable by any future
experiment or module without depending on this package's other pieces.

### `tower/experiments/__init__.py` (new)

```python
from dataclasses import dataclass, field
from typing import Callable


@dataclass(frozen=True)
class ExperimentResult:
    result_value: float
    result_label: str
    processing_ms: float
    stage_ms: dict[str, float]
    mean_intensity: float | None = None  # backward-compat only; set by
    # the baseline experiment specifically. None for every other
    # experiment -- never a mislabeled value under this field name.


# Import order here is deliberate, not incidental: ExperimentResult must
# be defined above this line. baseline.py/edge_detection.py both do
# `from tower.experiments import ExperimentResult`; by the time that runs,
# this (partially-initialized) module already has ExperimentResult set as
# an attribute, so the circular import resolves. Moving this import above
# the class definition breaks both submodules at import time.
from tower.experiments import baseline, edge_detection  # noqa: E402

EXPERIMENTS: dict[str, Callable[[bytes], ExperimentResult]] = {
    "baseline": baseline.run,
    "edge_detection": edge_detection.run,
}
```

`EXPERIMENTS` is a plain two-entry dict literal, not a plugin/discovery
system — no dynamic import, no filesystem scanning. This is the
"registry of one becomes registry of two, still fully static" analog to
V0.8's module container.

### `tower/experiments/baseline.py` (new)

```python
from tower.experiments import ExperimentResult
from tower.frame_processing import process_frame


def run(raw_bytes: bytes) -> ExperimentResult:
    result = process_frame(raw_bytes)  # unchanged, existing, tested
    return ExperimentResult(
        result_value=result.mean_intensity,
        result_label="mean_intensity",
        processing_ms=result.processing_ms,
        stage_ms={"total": result.processing_ms},
        mean_intensity=result.mean_intensity,
    )
```

`tower/frame_processing.py` is **not modified** — it keeps its own passing
tests and stays the single source of truth for the baseline computation.
This is deliberately a thin wrapper, not a rewrite: baseline's job is
proving nothing regressed, not demonstrating rich instrumentation. Its
`stage_ms` is honestly a single "total" entry because `process_frame`
doesn't expose finer-grained sub-timings, and splitting it just to make
the dict look richer would not be a real measurement.

### `tower/experiments/edge_detection.py` (new)

```python
import cv2
import numpy as np

from tower.experiments import ExperimentResult
from tower.instrumentation import StageTimer


def run(raw_bytes: bytes) -> ExperimentResult:
    timer = StageTimer()

    with timer.stage("decode"):
        array = np.frombuffer(raw_bytes, dtype=np.uint8)
        image = cv2.imdecode(array, cv2.IMREAD_COLOR)

    with timer.stage("blur"):
        gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
        blurred = cv2.GaussianBlur(gray, (5, 5), 0)

    with timer.stage("canny"):
        edges = cv2.Canny(blurred, 100, 200)

    with timer.stage("summarize"):
        edge_density = float(np.count_nonzero(edges)) / edges.size

    return ExperimentResult(
        result_value=edge_density,
        result_label="edge_density",
        processing_ms=timer.total_ms,
        stage_ms=timer.snapshot(),
    )
```

New code, written specifically for this milestone, so it uses `StageTimer`
properly and demonstrates the real multi-stage breakdown the baseline
experiment structurally can't (see above). Deliberately more expensive
than baseline on identical input — this is what makes "where does time
go" and "what happens when a heavier experiment can't keep up" answerable
from real numbers rather than a synthetic `sleep()`.

### `tower/modules/experimental_cv.py` (new)

```python
from tower.experiments import EXPERIMENTS, ExperimentResult
from tower.modules.base import Module, ModuleDataBehavior, ModuleDescriptor

DESCRIPTOR = ModuleDescriptor(
    id="experimental-cv",
    name="Experimental CV Lab",
    version="0.1.0",
    data_behavior=ModuleDataBehavior(
        persists_data=False,
        retains_raw_imagery=False,
        retention="none",
        supports_purge=False,
        transmits_externally=False,
    ),
)


class ExperimentalCVModule(Module):
    """Runs exactly one configured, stateless experiment function per frame.

    Stateless by design: no experiment allocates a persistent resource in
    _do_load(), which keeps V0.8's deferred resource-leak-on-partial-
    failure finding inert for this milestone. The first experiment that
    needs to hold a resource (e.g. a loaded model) is what should trigger
    revisiting that finding -- not a speculative fix now.
    """

    descriptor = DESCRIPTOR

    def __init__(self, experiment_name: str) -> None:
        super().__init__()
        self._experiment_name = experiment_name
        self._experiment_fn = None

    async def _do_load(self) -> None:
        fn = EXPERIMENTS.get(self._experiment_name)
        if fn is None:
            raise ValueError(
                f"unknown experiment {self._experiment_name!r}; "
                f"available: {sorted(EXPERIMENTS)}"
            )
        self._experiment_fn = fn

    async def _do_start(self) -> None:
        return None

    def _do_process(self, observation: bytes) -> ExperimentResult:
        return self._experiment_fn(observation)

    async def _do_stop(self) -> None:
        return None

    async def _do_unload(self) -> None:
        self._experiment_fn = None
```

An unknown/misconfigured experiment name fails inside `_do_load()`, which
`ModuleContainer.load_and_start()` already catches and turns into a
truthful `FAILED` state without crashing the process — this is exactly
the existing V0.8 failure path, exercised for a new reason, not a new
mechanism.

## Wiring changes

### `tower/config.py`

Add one field, following the existing `dev_mode` pattern exactly:

```python
@dataclass(frozen=True)
class Settings:
    host: str
    port: int
    dev_mode: bool
    cv_experiment: str


def get_settings() -> Settings:
    return Settings(
        host=os.environ.get("TOWER_HOST", "0.0.0.0"),
        port=int(os.environ.get("TOWER_PORT", "8000")),
        dev_mode=os.environ.get("TOWER_DEV_MODE", "true").lower() in ("1", "true", "yes"),
        cv_experiment=os.environ.get("TOWER_CV_EXPERIMENT", "baseline"),
    )
```

Default `"baseline"` when unset preserves existing V0.7/V0.8 wire behavior
for every existing test and deployment that doesn't set the new variable.

### `tower/main.py`

```python
app.state.module_container = ModuleContainer(
    ExperimentalCVModule(get_settings().cv_experiment)
)
```

replaces the `BaselineCVModule()` construction. `tower/modules/baseline_cv.py`
and `tests/test_baseline_cv_module.py` are deleted — not kept alongside the
new module as dead/parallel code. This is an intentional, expected
replacement: V0.8's `BaselineCVModule` docstring already said "V0.9
replaces this module in the same container slot."

### `tower/modules/container.py`

Add one property, mirroring the existing `state` property:

```python
@property
def descriptor(self) -> ModuleDescriptor:
    return self._module.descriptor
```

### `tower/routes/health.py`

```python
from fastapi import APIRouter, Request

@router.get("/health")
def health(request: Request) -> dict:
    container = request.app.state.module_container
    return {
        "status": "ok",
        "service": SERVICE_NAME,
        "version": API_VERSION,
        "module_state": container.state.value,
        "module_id": container.descriptor.id,
    }
```

`status: "ok"` keeps its existing meaning ("the Tower HTTP/WS server is
reachable") and is **not** overloaded to also mean "the module is
healthy" — those are two different truths (the V0.8 review's finding was
specifically that a FAILED module was invisible; conflating it into
`status` would make a truthful field lie about the server itself the
moment a module dies). `module_state`/`module_id` are additive.

### `tower/routes/ws.py`

`_handle_frame_message`'s success path changes from building
`{"type": "frame_result", "seq": ..., "mean_intensity": ..., "processing_ms": ...}`
to:

```python
payload = {
    "type": "frame_result",
    "seq": frame.seq,
    "processing_ms": result.processing_ms,
    "result_value": result.result_value,
    "result_label": result.result_label,
    "stage_ms": result.stage_ms,
}
if result.mean_intensity is not None:
    payload["mean_intensity"] = result.mean_intensity
await websocket.send_json(payload)
```

`seq` and `processing_ms` are unchanged in meaning and position.
`mean_intensity` is unchanged in meaning and is present with the exact
same value as before whenever `baseline` is the active experiment (the
default) — every existing test that asserts on it keeps passing
unmodified. It is simply absent (not `null`, not a wrong value) when a
different experiment is active, per Rule 3 ("unknown values remain
unavailable"). `result_value`/`result_label`/`stage_ms` are additive,
new fields.

`metrics.record_frame(...)` gains one additional argument,
`stage_ms=result.stage_ms`, passed alongside the existing
`cv_processing_ms=result.processing_ms` (unchanged).

### `tower/metrics.py`

Purely additive to `SessionMetrics`. `record_frame`'s existing parameters
(`seq`, `byte_count`, `receive_to_result_ms`, `cv_processing_ms`) are
**unchanged** — `cv_processing_ms` keeps meaning "total experiment time,"
exactly as today, so every existing `SessionMetrics` test and the V0.7
report's documented field names stay valid. A new optional parameter is
added:

```python
def record_frame(
    self,
    seq: int,
    byte_count: int,
    receive_to_result_ms: float,
    cv_processing_ms: float,
    stage_ms: dict[str, float] | None = None,
) -> None:
    ...  # existing body unchanged
    if stage_ms:
        for stage_name, ms in stage_ms.items():
            self._stage_ms.setdefault(stage_name, []).append(ms)
```

`__init__` adds `self._stage_ms: dict[str, list[float]] = {}`.
`snapshot()` adds, alongside the existing keys:

```python
"stage_ms_avg": {k: round(_avg(v), 3) for k, v in self._stage_ms.items()},
"stage_ms_max": {k: round(max(v), 3) for k, v in self._stage_ms.items()},
```

reusing the existing `_avg()` helper unchanged. Every existing snapshot
key keeps its existing meaning and value.

## What this answers from the design-goal question list

- **Per-stage latency** — `stage_ms` per frame, `stage_ms_avg`/`stage_ms_max` per session, both experiments populate it (baseline shallowly, edge_detection richly, by honest necessity — see above).
- **End-to-end frame latency / throughput** — already answered by V0.7/V0.8's existing `receive_to_result_ms`, `effective_fps`, `bandwidth_bps` in `SessionMetrics.snapshot()` — unchanged, just now sitting next to per-stage data for the same frame.
- **CPU/GPU bottleneck location** — CPU: `process_cpu_percent`/`process_rss_bytes` (existing) plus the new `stage_ms` breakdown pinpoints which CV operation dominates. GPU: not answerable in V0.9 — no GPU experiment exists (explicit non-goal).
- **Which operations benefit from GPU** — not answerable yet either; this milestone's job is producing the CPU baseline numbers a future GPU experiment would need to beat.
- **Backpressure behavior under a heavy experiment** — answered by observation, not new mechanism: run `edge_detection`, watch `receive_to_result_ms` under the existing strict sequential path.
- **Separating expensive work from the real-time path** — not attempted in V0.9; both experiments run synchronously inline, same as `BaselineCVModule` did. Worth flagging as a real open question for a *later* Lab experiment once a genuinely expensive (e.g. model-based) experiment exists to separate.

## V0.8 deferred issues — reassessed for this scope

- **Event-loop lifecycle mismatch** — still inert. Neither experiment's `_do_load`/`_do_start` creates loop-bound objects (a dict lookup and two no-ops). Constraint carried forward unchanged: experiment code must not create `asyncio.Lock`/`Queue`/background tasks/etc.
- **Resource leak on load-succeeds-start-fails** — still inert, by construction: `_do_load()` only performs a dict lookup (no allocation to leak) and `_do_start()` is a no-op. Explicitly flagged as the thing to revisit the moment a stateful (model-loading) experiment is added — not fixed speculatively here.
- **No external visibility into a FAILED module** — addressed in this milestone via the `/health` addition above (approved).

## Testing strategy

Same discipline as V0.8: `.venv/Scripts/python.exe -m pytest`, real objects,
no mocks, TDD.

- `tests/test_instrumentation.py` — `StageTimer` records real elapsed time for a stage, `snapshot()`/`total_ms` are correct.
- `tests/test_experiments_baseline.py` — `baseline.run()` matches `process_frame()` directly (same pattern as the V0.8 `BaselineCVModule` test it replaces).
- `tests/test_experiments_edge_detection.py` — `edge_detection.run()` on a known synthetic image (e.g. a hard black/white edge) produces a higher `result_value` than a uniform-color image; `stage_ms` has all four expected keys; `mean_intensity` is `None`.
- `tests/test_experimental_cv_module.py` — full lifecycle (mirrors the deleted `test_baseline_cv_module.py`) for both experiment names; unknown experiment name → `FAILED` after `load_and_start()` (via `ModuleContainer`, not the raw `Module`, to exercise the real catch path).
- `tests/test_health.py` — extended: `module_state == "active"`, `module_id == "experimental-cv"`.
- `tests/test_ws_frames.py` and friends — expected to need **zero changes**: default config is `baseline`, `mean_intensity` keeps its existing value/position, so every existing assertion should keep passing unmodified. This is the regression signal.
- New: a test asserting the `edge_detection` wire path — `monkeypatch.setenv("TOWER_CV_EXPERIMENT", "edge_detection")` before `create_app()`, confirm `frame_result` has `result_label == "edge_density"` and no `mean_intensity` key.
