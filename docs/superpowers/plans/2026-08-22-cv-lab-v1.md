# Experimental CV Lab V1 — implementation plan

**Status:** PLAN. Written 2026-08-22 on `world-builder/v1` @ `ffe39cc`,
after the World Builder closeout. Cartridge 1 of the sequential cartridge
run.

**Reconciles:** `guidelines/docs/modules/EXPERIMENTAL-CV.md`, written
before any of this existed.

---

## 1. What the Lab is for, and what it is not

From its module doc: *"a controlled place to test computer-vision
techniques on first-person glasses data without contaminating production
modules"*. Two rules govern everything below:

- **Every experiment must expose useful measurements.** An experiment
  that returns a number nobody can act on is not an experiment.
- **It must not become a random collection of models.** Each addition
  answers a question another part of the platform actually has.

It must also **never mutate authoritative World Builder state**. The Lab
may read; it must not write.

## 2. What exists today

| Piece | Reality |
|---|---|
| `tower/modules/experimental_cv.py` | One `Module`. Runs one stateless function per frame |
| `tower/modules/depth_cv.py` | A **second** `Module` class with the **same descriptor id**, existing only because the depth experiment holds a model across frames |
| `tower/experiments/__init__.py` | `EXPERIMENTS: dict[str, Callable[[bytes], ExperimentResult]]` — stateless callables only |
| `ExperimentResult` | `result_value: float`, `result_label: str`, `processing_ms`, `stage_ms`, `mean_intensity` |
| Experiments | `baseline` (mean intensity), `edge_detection` (edge density), `depth` (MiDaS-small, unregistered, special-cased) |

## 3. The two things blocking a useful Lab

### 3.1 One scalar is not a measurement channel

`ExperimentResult` carries exactly one number plus its label. An
experiment measuring frame quality has six things to say; one measuring
optical flow has four; one measuring detection has a count, a class
breakdown and a score distribution. Today all of them must pick one
number and throw the rest away — which directly contradicts "every
experiment must expose useful measurements".

`CARTRIDGE-GROUNDWORK.md` lists "a non-scalar result channel" as missing
infrastructure that four other cartridges are waiting on. **It is the
Lab's own type.** Fixing it here is not scope creep; it is the one
cartridge that owns the file.

**Decision:** add `metrics: dict[str, float] = {}` to `ExperimentResult`.
Additive. `result_value`/`result_label` stay as the mandatory **headline**
metric — a discipline, not a limitation: an experiment that cannot name
its single most important number has not decided what it is measuring.

**Wire:** `frame_result` gains a `metrics` object **only when non-empty**.
That is an additive change under `TOWER-TO-IOS.md` §7 rule 3 — a client
that ignores the field is unaffected.

**Not doing:** arbitrary nested JSON, structured objects, geometry, or
detection lists on the wire. `dict[str, float]` is a measurement channel,
not a general result channel. The general one is V1.0 work and stays
blocked.

### 3.2 A stateful experiment costs a whole Module class

`DepthEstimationModule` exists solely because `DepthEstimation` holds a
model. Two `Module` subclasses now share one descriptor id. V1 adds two
more stateful experiments (a detector holds weights; optical flow holds
the previous frame), and on the current design each would need its own
`Module` class.

**Decision:** one `Experiment` protocol — `load(...)`, `run(bytes)`,
`release()` — and a registry of **factories** rather than functions.
`ExperimentalCVModule` hosts any of them; `depth_cv.py` collapses into it.
Stateless experiments are wrapped so they keep costing nothing to write.

This deletes a class rather than adding one, and it is what makes the
experiments below possible without four more.

**Explicitly not resolved:** `_do_load()` remains synchronous. The
unbounded-blocking lifecycle gap is a standing decision gate
(`docs/superpowers/plans/2026-08-20-object-memory-first-slice.md`) and
this refactor must not silently pick an option in it.

## 4. The V1 experiment set

Costs measured on this host at 640×360, 20 iterations, before writing any
of them — so the set is chosen from numbers rather than from taste.

| Experiment | Headline | Also measures | Cost | State |
|---|---|---|---|---|
| `frame_quality` | sharpness (Laplacian variance) | gradient energy, entropy, contrast, edge density, over/under-exposed pixel fraction | ~3.5 ms | none |
| `feature_detection` | usable ORB keypoints | mean response, spatial coverage across an 8×8 grid, describe time | ~2.6 ms | none |
| `optical_flow` | median flow magnitude (px) | tracked fraction, forward–backward error, direction dispersion | ~2.9 ms | previous frame |
| `object_detection` | detections above threshold | person count, mean/max score, class histogram, inference ms | ~31 ms CPU | model |
| `redaction_impact` | keypoint retention ratio | keypoints lost, fraction of survivors on the redaction boundary | ~3.5 ms | none |

Existing `baseline` and `edge_detection` stay. `depth` stays, moved onto
the unified protocol.

**Why each earns its place:**

- **`frame_quality`** is the cheap-early-rejection question every cartridge
  has. World Builder already answers a private version of it; the Lab is
  where the thresholds get measured rather than guessed.
- **`feature_detection`** measures whether a real indoor scene gives
  enough texture to track — the first thing physical footage must settle,
  and currently a synthetic-only claim.
- **`optical_flow`** measures apparent motion independently of World
  Builder's tracker, which is what makes it an evaluation rather than a
  restatement. Sparse LK is chosen over dense Farneback because dense
  measured **25.4 ms against 2.9 ms** for the same question; the benchmark
  records that comparison so the choice stays evidence.
- **`object_detection`** (torchvision `ssdlite320_mobilenet_v3_large`,
  COCO, 13.4 MB, already-installed dependency) exists because **Cartridge
  3 needs this measurement before it can choose a detector**, and the
  module doc's promotion path says measure in the Lab first. It yields
  `person`, `chair`, `dining table` — literally Scene Understanding's
  example questions.
- **`redaction_impact`** answers `plan.md` §F's "does face redaction
  interfere with feature tracking or geometry?" with a number. The World
  Builder review found informally that 100% of surviving near-region
  keypoints sat on the blur boundary; this makes that reproducible.

**Rejected for V1:**

| Rejected | Why |
|---|---|
| Face detection | `cv2.CascadeClassifier` does not exist in this OpenCV 5 build; `FaceDetectorYN` exists as an API but no model ships and none is on disk (verified: zero `.onnx`/`.xml`/`.caffemodel` anywhere under `cv2/`). There is also no face imagery to validate against. `redaction_impact` measures the *consequence* of redaction without pretending to detect a face |
| Dense optical flow as an experiment | 8.8× the cost of sparse for the same headline. It appears in the benchmark as a comparison, which is where a rejected alternative belongs |
| Semantic segmentation, instance segmentation, tracking-by-detection, image retrieval, novelty detection | All in the module doc's candidate list. None answers a question another cartridge has *today*. Adding them would be exactly the "random collection of models" the brief forbids |
| A GPU variant of anything | torch is CPU-only on this host and there is no C++/CUDA compiler. Recording a GPU number we cannot produce would be a fabrication |
| A new dataset-recording mechanism | `tower/capture.py` already is one, shared and privacy-reviewed. The Lab points at it |

## 5. Evaluation, not just instrumentation

The module doc requires hypothesis / dataset / metric / baseline / result.
The World Builder review's test-quality finding applies with full force:
**every test asserts against independent truth, never against what the
code produced.**

- `optical_flow` is evaluated against the synthetic harness's **known**
  camera translation — a pure sideways walk must produce a dominant
  horizontal flow direction and a magnitude that grows with step size.
- `frame_quality` is evaluated against **deliberately degraded** input:
  a Gaussian-blurred frame must score lower sharpness than its original,
  and an over-exposed frame must report a higher clipped fraction.
- `feature_detection` is evaluated against a **textureless** frame, which
  must yield near-zero keypoints, and against a textured one, which must
  not.
- `object_detection` is evaluated against a frame with a **known** object
  count where the harness can render one.
- `redaction_impact` is evaluated against a **known** redaction rectangle.

## 6. Isolation

A test extends `tests/test_architecture_boundaries.py`:

- `tower/experiments/**` and `tower/modules/experimental_cv.py` must not
  import `tower.world_builder` or `tower.object_memory`.
- No experiment may construct a `WorldStore` or write under a world root.

The Lab reading a world for visualisation is a future question. Today it
does not, and the test says so.

## 7. Deliverables

1. `ExperimentResult.metrics` + wire exposure, with tests.
2. Unified `Experiment` protocol and factory registry; `depth_cv.py`
   removed; `ExperimentalCVModule` hosts everything.
3. Five new experiments, each with ground-truth-anchored tests.
4. `scripts/cv_lab_benchmark.py` — every experiment across resolutions,
   per-stage timings, headline and full metrics, plus the sparse-vs-dense
   flow comparison. JSON and text output.
5. `guidelines/docs/modules/EXPERIMENTAL-CV.md` reconciled against reality.
6. A measured report under `guidelines/docs/reports/`.
7. Architecture-boundary tests.

## 8. Definition of done

Full suite green; new tests assert against independent truth; benchmark
produces real numbers on this host; no experiment writes cartridge state;
`ExperimentResult` change is additive and the existing wire contract is
unbroken; docs distinguish IMPLEMENTED / PLANNED / EXPERIMENTAL /
BLOCKED; adversarial review completed and findings fixed or justified;
committed with a clean tree.
